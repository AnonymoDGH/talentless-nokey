# TALENTLESS — Formato de canción (custom songs)

## 1. Qué es una "custom song"

Un archivo de **texto plano** (`.txt`) que contiene un **script Lua** con una secuencia de
llamadas al API de TALENTLESS. Se añade desde la UI con el botón `+` (usa `add_song.lua`),
que guarda el texto en `TALENTLESS_CUSTOM_SONGS/<nombre>.txt`.

Al reproducirla:
- `bpm = tonumber(bpmbox.Text)` → **el tempo lo toma de la caja "bpm" de la UI**. Debes
  escribir ahí el BPM objetivo ANTES de darle play.
- El script se ejecuta con `loadstring(songcode)()`.

## 2. API del formato (definido en `loader_main.lua`)

```lua
keypress(keys, beats, bpm)   -- pulsa una tecla (o un acorde si keys tiene varios caracteres)
rest(beats, bpm)             -- silencio: avanza el tiempo beats/bpm*60 segundos
adjustVelocity(v)            -- v en 0..1 (matiz/velocidad); avanzado
pedalDown() / pedalUp()      -- pedal de sustain (tecla Espacio); avanzado
finishedSong()               -- marca el final (obligatorio al terminar)
```

Variables globales disponibles dentro de la canción:
- `bpm`  → el BPM actual (viene de la caja de la UI).
- `x`    → tiene el valor `"hi"`. **Usado como "nota corta/staccato"**: `keypress("t", x, bpm)`.

### Semántica exacta (¡clave!)

- **La duración de la canción la marcan los `rest()`.** El reproductor recorre la lista de
  eventos en orden: los `keypress` se lanzan en corrutinas (no bloquean) y los `rest` esperan.
  Por tanto: `tiempo_total ≈ Σ (beats_de_cada_rest / bpm_del_rest) * 60` segundos.
- **`beats` en `keypress`:**
  - Si es un número → nota normal; se mantiene 50–90 % de `(beats/bpm)*60` s.
  - Si NO es número (caso `x`) → **nota corta** (staccato), duración aleatoria pequeña.
- **Acordes:** se forma un acorde concatenando caracteres en un mismo `keypress`
  (`keypress("PJ", x, bpm)`) **o** escribiendo varios `keypress` seguidos con el MISMO valor
  de `beats` (se fusionan). Ejemplo real (NOCTURNE): `keypress("@(hv", x, bpm*2)`.
- **El `bpm` pasado a `rest` puede escalarse** para cambiar tempo localmente.
  Ej. real (NOCTURNE): `rest(1, bpm*2)` → cada slot dura `60/(2*bpm)` s (la mitad).
- Una nota/corche por "slot", seguida SIEMPRE de un `rest` que define el hueco.
  Para separar dos notas NO pueden ir consecutivas sin rest (se fusionarían).

### Ejemplo mínimo válido

```lua
-- Generated by MIDI2LUA --
-- MIDI88: OFF --
-- Short Notes: ON --
-- Note Velocity: OFF --
-- Sustain Pedal: OFF --
-- Midi Spoofer: OFF --

keypress("t", x, bpm)
rest(0.5, bpm)
keypress("y", x, bpm)
rest(0.5, bpm)
keypress("uio", x, bpm)   -- acorde
rest(1, bpm)
finishedSong()
```

## 3. Mapa de teclas → notas (rango 88 teclas, A0–C8)

Cada carácter es una tecla física; el juego (Piano Rooms) la interpreta como la nota indicada.
Las mayúsculas y símbolos son **teclas negras** (el reproductor mantiene Shift automáticamente).

| Octava | Teclas |
|---|---|
| A0–B1 | `Ctrl+1` A0, `Ctrl+2` A#0, `Ctrl+3` B0, `Ctrl+4` C1, `Ctrl+5` C#1, `Ctrl+6` D1, `Ctrl+7` D#1, `Ctrl+8` E1, `Ctrl+9` F1, `Ctrl+0` F#1, `Ctrl+q` G1, `Ctrl+w` G#1, `Ctrl+e` A1, `Ctrl+r` A#1, `Ctrl+t` B1 |
| C2–B2 | `1` C2, `!` C#2, `2` D2, `@` D#2, `3` E2, `4` F2, `$` F#2, `5` G2, `%` G#2, `6` A2, `^` A#2, `7` B2 |
| C3–B3 | `8` C3, `*` C#3, `9` D3, `(` D#3, `0` E3, `q` F3, `Q` F#3, `w` G3, `W` G#3, `e` A3, `E` A#3, `r` B3 |
| C4–B4 | `t` C4, `T` C#4, `y` D4, `Y` D#4, `u` E4, `i` F4, `I` F#4, `o` G4, `O` G#4, `p` A4, `P` A#4, `a` B4 |

> C4 `t`, D4 `y`, E4 `u`, F4 `i`, G4 `o`, A4 `p`, B4 `a`.

## 4. Convenciones observadas en canciones reales

- Cabecera de comentarios `-- Generated by MIDI2LUA --` con flags (MIDI88 / Short Notes /
  Note Velocity / Sustain Pedal / Midi Spoofer). No es obligatoria, pero ayuda.
- Predomina `keypress(chord, x, bpm)` + `rest(...)`. La mayoría usa **notas cortas (`x`)**.
- Los acordes se concatenan en un solo `keypress`; el máximo visto es 10 caracteres.
- Densidad típica: 200–2500 eventos de nota; canciones de 1–5 min.
- Se termina con `finishedSong()`.

## 5. Cómo se compone (básico → avanzado)

**Básico**
- Melodía monofónica: una `keypress` + un `rest` por nota.
- Ritmo: elegir BPM y usar `rest` de 0.25 / 0.5 / 1 / 2 beats.
- Tonalidad: ceñirse a las 7 notas de la escala.

**Intermedio**
- Acordes (bloques): concatenar 3–4 notas (`"tio"`).
- Bajo separado: usar octavas graves (`1`–`7`, `8`–`r`) en los tiempos fuertes.
- Arpegios: repartir un acorde en notas sucesivas con rests cortos.
- Forma musical: intro / A / B / A' / outro.

**Avanzado**
- Voces simultáneas: melodía en octava central + bajo en grave + acorde en sostenido,
  todo en el mismo slot (`keypress("t"...)` y `keypress("1"...)` con el mismo `beats` → se fusionan).
- Dinámica con `adjustVelocity(0..1)`.
- Sustain con `pedalDown()` / `pedalUp()`.
- Registro amplio (A0–C8) con `Ctrl+...`.
- Escalado de tempo local (`rest(b, bpm*2)`).
- Rubato/ritardando: usar rests de duración variable.

## 6. Duración

`duracion_s = Σ rest (beats / bpm_pasado_al_rest) * 60`

Para ≥ 60 s con BPM 100 → ≥ 100 beats de rests. Referencia: una pieza de ~2 min a 100 BPM
suele tener ~1200–2200 eventos.

## 7. Validación

Hay un validador en `validate_song.lua` (Lua 5.1):

```
lua validate_song.lua <ruta_song.txt> <bpm>
```

Comprueba que compile, que no use identificadores desconocidos, cuenta eventos/acordes y
calcula la duración. Añade también `finishedSong()`.
